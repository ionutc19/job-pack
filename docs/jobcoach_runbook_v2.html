Job Coach - Runbook operational, deployment, update si migrare

Document de knowledge pentru oameni si AI (Copilot / Claude)
Data: 22.06.2026 — Versiunea 2

Scopul documentului

Acest document are 3 scopuri principale:

  • sa poata fi urmarit cap-coada pentru 4 scenarii clare: deploy de la zero, update-uri ulterioare, publicare in Google Play, mutare pe alta infrastructura;
  • sa fie o sursa de knowledge pentru AI (Copilot, Claude) daca istoricul chat-ului dispare si trebuie reconstruit contextul tehnic si operational;
  • sa documenteze toate secretele, cheile si configurarile necesare pentru a reconstitui environment-ul complet.

Limba folosita este in principal romana fara diacritice. Unde termenii tehnici sunt mai clari in engleza, au fost pastrati in engleza.

Context tehnic si arhitectura

Aplicatia este impartita in 2 componente majore:

  • mobile: aplicatia Flutter Android, cu modulele Job Fit, Cover Letter, Profile Boost;
  • server: backend Python/FastAPI publicat in Azure App Service, cu PostgreSQL Flexible Server ca baza de date.

Capitolul 1 - Cum fac deploy de la zero

Acest capitol descrie constructia unui environment nou, pornind de la zero. Se presupune ca ai acces la Azure, GitHub si local workstation Windows cu Flutter, Android Studio, Azure CLI si Git instalate.

1.1. Prerequisites locale

  • Git instalat si configurat (git clone, git pull, git push);
  • Azure CLI autentificat: az login;
  • Flutter SDK functional: flutter doctor fara erori critice;
  • Android Studio + Android SDK + emulator sau telefon Android pentru testare;
  • Python local pentru operatii auxiliare, daca este nevoie;
  • Acces la contul de GitHub si la subscription-ul Azure.

1.2. Clonare repository

git clone https://github.com/ionutc19/job-pack
cd C:\github\job-pack

Capitolul 2 - Google Play: configurare completa si publicare

Acest capitol acopera tot ce trebuie configurat in Google Play Console, Google Cloud si Azure pentru ca subscriptiile, verificarea achizitiilor si publicarea sa functioneze corect.

2.1. Google Play Console - subscriptii

In Play Console → Monetize → Products → Subscriptions, creeaza:

Product IDNumePretTier
jobcoach_premium_monthlyPremium$3.99/lunapremium - 20 requests/day/module, fara ads
jobcoach_pro_monthlyPro$9.99/lunapro - 100 requests/day/module, fara ads
Aceste product ID-uri sunt hardcodate in mobile/lib/services/billing_service.dart si in server/app/services/subscription_service.py. Daca le schimbi in Play Console, trebuie schimbate si in cod.

2.2. Google Cloud - service account pentru purchase verification

Backend-ul verifica achizitiile server-side prin Google Play Developer API. Pentru asta ai nevoie de un service account.

  1. Google Cloud Console → IAM & Admin → Service Accounts → Create Service Account
  2. Nume: jobcoach-play-billing
  3. Nu adauga roluri IAM (nu e nevoie)
  4. Creeaza key: tab Keys → Add Key → Create new key → JSON → Download
  5. Leaga in Play Console: Play Console → Setup → API access → Link Google Cloud project → Grant access service account-ului

2.3. Setare GOOGLE_PLAY_CREDENTIALS_JSON in Azure

Copiaza tot continutul fisierului JSON descarcat si seteaza-l ca app setting:

az webapp config appsettings set `

  --settings GOOGLE_PLAY_CREDENTIALS_JSON='<CONTINUTUL_COMPLET_AL_JSON-ULUI>'

Securitate: Daca private key-ul a fost expus (de exemplu in chat, email, repo), roteste-l imediat: Google Cloud Console → Service Accounts → jobcoach-play-billing → Keys → Add Key (noua) → Delete key (veche) → Re-ruleaza comanda az cu noul JSON.

Troubleshooting - probleme intalnite si rezolvarea lor

T1. Emulator sau telefon nu este vazut corect

$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
$emu = "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe"
& $adb kill-server
& $adb start-server
& $adb devices
# emulator offline -> cold boot
& $emu -avd "Pixel_8_Pro" -no-snapshot-load

T2. adb / emulator / keytool nu sunt recunoscute in PowerShell

Pe Windows, foloseste path complet si operatorul & in PowerShell.

T3. Eroare gradle legata de google_mobile_ads vechi

Solutia: upgrade la versiune compatibila (ex: 9.0.0), apoi flutter clean si flutter pub get.

T4. compileSdk prea mic pentru dependinte noi

Solutia: ridica compileSdk (si targetSdk) la 36 in build.gradle.kts.

T5. App crash la launch: MainActivity ClassNotFoundException

Cauza: namespace / applicationId / AndroidManifest / folder path pentru MainActivity nu sunt aliniate. Toate trebuie sa fie coerente pe com.ionutc19.jobcoach.

T6. Debug merge, release APK nu porneste

Cauza tipica: release-only issue (R8 / minify). Solutia: logcat pe telefon, investigheaza cu proguard-rules.pro.

T7. PDF upload esueaza cu 'Could not extract text'

PDF scanat / image-only: fara OCR, mesaj clar. PDF corupt / protejat: mesaj specific. PDF text-based: trebuie sa mearga.

T8. Consent / permisiuni la upload documente

Cu Storage Access Framework, nu trebuie broad storage permission. UX-ul explica ce se intampla si afiseaza fisierul selectat + remove/replace.

T9. Iconita / branding nu se actualizeaza

Dezinstaleaza aplicatia si reinstaleaz-o.

T10. Startup.sh / CRLF / Alembic in Azure

Verifica startup.sh sa fie LF, fara caractere ascunse.

T11. Zip deploy esueaza sau app-ul nu porneste dupa deploy

Verifica structura zip-ului (fisierele direct, nu folder-ul server ca root). Dupa deploy: /api/health si az webapp log tail.

T12. Deploy 502 - build automation not enabled

Seteaza SCM_DO_BUILD_DURING_DEPLOYMENT=true inainte de deploy:

az webapp config appsettings set `
  --resource-group "rg-jobcoach-prod" `
  --name "jobcoach-api-ionut-se" `
  --settings SCM_DO_BUILD_DURING_DEPLOYMENT=true

T13. Rotire chei Google Cloud service account

Daca private key-ul a fost expus:

  1. Google Cloud Console → IAM → Service Accounts → jobcoach-play-billing
  2. Tab Keys → Add Key → Create new key → JSON → Download
  3. Re-ruleaza: az webapp config appsettings set ... GOOGLE_PLAY_CREDENTIALS_JSON='<NOU_JSON>'
  4. Sterge cheia veche din Google Cloud Console
  5. Restart App Service: az webapp restart ...
